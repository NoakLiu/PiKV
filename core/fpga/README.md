# PiKV-FPGA Hardware Stack

**Verilog RTL** + **AXI-Lite / CXL DMA** + **C host** + **Vivado bitstream** (paper §3.5).

This document states the **hardware platform**, **bandwidth assumptions**, and
**how end-to-end gains are measured**, so FPGA/CXL claims are not purely conceptual.

## 1. Hardware platform (canonical)

| Item | Specification |
|------|----------------|
| Board | **AMD Alveo U55C** |
| FPGA part | `xcu55c-fsvh2892-2L-e` (`PIKV_PART`) |
| On-card memory | **16 GB HBM2**, datasheet peak **~460 GB/s** |
| User clock | **300 MHz** (`pikv_u55c.xdc`, period 3.333 ns) |
| Host attach | PCIe Gen4 x16 via **XDMA**; optional **CXL Type-3.mem** expander |
| Constraints | `vivado/constraints/pikv_u55c.xdc` |
| Generic bring-up | `vivado/constraints/pikv_generic.xdc` (non-U55C shells) |

**Bring-up without CXL silicon:** map `m_axi_*` from `pikv_soc_top` to on-card HBM/DDR
through `axi_noc` (see `vivado/ip/README.md`). Functional correctness is validated in
Icarus sims (`tb/`); silicon numbers require `xbutil` + PCIe/CXL counters.

Default tile (matches paper §3.5): `E=64`, `S=256`, `k=4`, `K=16`, `d=128`, `ρ=4`.

## 2. Architecture

```
Host PCIe ──► [XDMA] ──AXI-Lite──► pikv_soc_top ──► PiKV-CTRL / engines
                      └──AXI-MM──► pikv_cxl_dma ──► CXL Type-3 DDR (KV pool)
                                   (or HBM via axi_noc for prototype)
```

| Module | Interface | Role |
|--------|-----------|------|
| `pikv_axi_lite_slave` | AXI4-Lite | Host MMIO (BAR0) |
| `pikv_soc_top` | AXI-L + AXI-MM | SoC integration top |
| `pikv_cxl_dma` | AXI4 master | KV body DMA to CXL.mem / HBM |
| `pikv_axi_dma_master` | AXI4 | Single-beat read/write |
| `pikv_cxl_mem_model` | AXI4 slave | Simulation memory |

## 3. Bandwidth model (explicit assumptions)

We **do not** report HBM peak as achieved application throughput. Artifact defaults:

| Path | Effective payload BW (default) | Where set |
|------|--------------------------------|-----------|
| CXL.mem / off-chip KV body | **64 GB/s** | `FPGAConfig.mem_bandwidth_gbps` |
| Host↔FPGA PCIe (meta/DMA) | **32 GB/s** | `benchmark_hw.HardwarePlatformSpec` |
| HBM2 peak (on-card datasheet) | **460 GB/s** | reported for context only |

Latency model (paper §3.5):

\[
T_{\mathrm{fpga}} = T_{\mathrm{route}} + k\cdot(T_\Gamma + K\cdot(T_{\mathrm{ddr}} + T_{\mathrm{codec}}))
\]

implemented in `estimate_fpga_latency_us()` (`config.py`).

### Reproduce bandwidth / E2E comparison

```bash
# From repo root
python -m core.fpga.benchmark_hw
python -m core.fpga.benchmark_hw --json > /tmp/pikv_fpga_hw.json
python examples/fpga_offload_example.py
```

Output includes: platform table, **metadata vs full-path** µs/token, CPU baseline,
comparative speedups, BW sensitivity sweep, and JSON export. FPGA-sim wall-clock is a
**functional** simulator, not silicon timing; use modeled \(T_{\mathrm{meta}}\) for the
SmartNIC offload claim and \(T_{\mathrm{full}}\) for CXL body gather.

### On-silicon measurement checklist

1. Program bitstream: `./build_fpga.sh bitstream` then `xbutil program -d <bdf> -p <bit>`
2. Record CXL/HBM effective BW with vendor counters / `perf` / XDMA throughput tests
3. Replace `mem_bandwidth_gbps` / PCIe BW in the report with measured values
4. Re-run `python -m core.fpga.benchmark_hw --json` and archive JSON with the paper tables

## 4. End-to-end gains (what is / is not claimed)

| Comparison | Method | Claim type |
|------------|--------|------------|
| CPU metadata path vs analytic \(T_{\mathrm{fpga}}\) | `benchmark_hw.end_to_end_comparison` | **Modeled** metadata offload gain |
| CPU vs FPGA software sim | same harness | Functional correctness + software proxy only |
| Full LLM decode wall-clock on U55C | requires deployed board + GPU host | **Not** auto-generated by this repo without hardware |

Comparative baselines in the harness:

- **CPU baseline**: PyTorch Linear Top-k + naive compress/schedule proxy
- **FPGA path**: `create_pikv_fpga(simulate=True)` engines (ScoreFuse / Codecρ / scheduler)
- **Analytic FPGA**: `estimate_fpga_latency_us`

## 6. Build

```bash
./build_fpga.sh all          # C lib + RTL sim + test
./build_fpga.sh sim-soc      # AXI-Lite + CXL mem model sim
./build_fpga.sh vivado       # Create Vivado project (pikv_soc_top)
./build_fpga.sh bitstream    # Synth + impl + .bit (needs Vivado + license)
./build_fpga.sh bd           # Optional XDMA block design
```

Env:
- `PIKV_PART=xcu55c-fsvh2892-2L-e` (Alveo U55C)
- `PIKV_JOBS=8`

Bitstream output: `vivado/project/pikv_fpga.runs/impl_1/*.bit`

## 7. MMIO map

| Offset | Register |
|--------|----------|
| 0x000 | STATUS |
| 0x004 | CTRL |
| 0x008 | QUERY |
| 0x00C | TOKEN_ID |
| 0x040 | CXL_BASE[31:0] |
| 0x044 | CXL_BASE[63:32] |
| 0x048 | DMA_XFER_CNT |
| 0x04C | DMA_BUSY |
